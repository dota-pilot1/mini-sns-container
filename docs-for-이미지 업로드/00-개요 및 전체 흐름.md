# 00. 이미지 업로드 기능 — 개요 및 전체 흐름

## 목표
방(Room) 에 다중 이미지 업로드 + 대표 이미지 설정 + 목록(카드/테이블)에 썸네일 미리보기.
방 상세는 드로어 → 별도 페이지(`/rooms/:roomId`) 로 분리.

## 아키텍처 (presigned URL 방식 채택)

```
프론트                               서버                           S3
 │ 1. presign 요청 (파일명/타입)  →   │                               │
 │ 2. {key, uploadUrl} ←              │                               │
 │ 3. PUT uploadUrl (파일 바이트) ────────────────────────────────→  │
 │ 4. POST /rooms/{id}/images {key}  →│                               │
 │                                    │ 5. RoomImage DB 저장          │
 │ 6. 이미지 목록 응답 ←              │                               │
```

### 왜 presigned URL?
- 서버 메모리·네트워크 부담 없음 (파일 바이트가 서버를 거치지 않음)
- 대용량·다중 업로드에 유리
- S3 권한을 프론트에 노출하지 않음 (URL은 5~15분 TTL)

### 대안 (쓰지 않음)
- 서버 multipart 프록시: 구현은 쉽지만 서버 대역폭 낭비

## 데이터 모델

```
RoomImage
├── id (PK)
├── roomId (FK)
├── s3Key            # 예: rooms/42/uuid-filename.jpg
├── contentType
├── sizeBytes
├── sortOrder        # 갤러리 순서
├── isPrimary        # 대표 이미지 여부 (room당 1개)
└── createdAt
```

조회 시 `s3Key` → `https://{bucket}.s3.{region}.amazonaws.com/{key}` 로 변환해 응답.
(버킷을 private 유지하려면 GET 도 presigned URL 로 바꿀 것)

## 스텝 순서

| # | 스텝 | 범위 |
|---|------|------|
| 01 | S3 인프라 세팅 | build.gradle, properties, S3Client 빈 |
| 02 | RoomImage 도메인 추가 | 엔티티, 리포지토리, Room 과 관계 |
| 03 | Presigned URL 업로드 API | `POST /api/uploads/presign` |
| 04 | RoomImage CRUD API | 등록·조회·삭제·대표 지정 |
| 05 | 프론트 API 클라이언트 + 훅 | `image-api.ts`, React Query 훅 |
| 06 | 방 상세 페이지 분리 | 드로어 → `/rooms/:roomId` |
| 07 | 이미지 업로드 UI | 드롭존, 갤러리, 대표 지정 |
| 08 | 카드·테이블 썸네일 | 목록 미리보기 |

## 완료 기준 (DoD)
- 방 상세 페이지에서 이미지 여러 장 업로드·삭제 가능
- 대표 이미지 지정 시 카드/테이블 목록에서 해당 이미지가 썸네일로 보임
- 새로고침 후에도 유지됨 (DB 영속)
- `.env` 누락 시 애플리케이션이 명확한 에러로 실패 (조용히 죽지 않음)
