# 01. S3 인프라 세팅

## 목표
Spring Boot 서버가 AWS S3 에 presigned URL 을 발급하고 객체를 조작할 수 있게 하는 최소 세팅.

## 체크리스트

### 1) 의존성 추가 (`stay-ops-server/build.gradle`)
```gradle
implementation platform('software.amazon.awssdk:bom:2.25.70')
implementation 'software.amazon.awssdk:s3'
implementation 'software.amazon.awssdk:s3-transfer-manager'  // 선택
```
> NestJS 프로젝트는 `@aws-sdk/client-s3` 를 썼지만 Java 에선 AWS SDK v2 사용.

### 2) `.env` 로더 확인
- 이미 `.env` 는 서버 루트에 생성됨
- Spring Boot 가 `.env` 를 자동 읽지 않음 → 두 가지 선택:
  - (A) `spring-dotenv` 라이브러리 추가 (간단)
  - (B) IntelliJ Run Configuration / `docker-compose` 에서 주입 (운영 친화)
- **권장**: (A) 로컬 편의 우선, prod 는 환경변수로 오버라이드

### 3) `application.yaml` 에 블록 추가
```yaml
aws:
  region: ${AWS_S3_REGION:ap-northeast-2}
  credentials:
    access-key: ${AWS_ACCESS_KEY_ID:}
    secret-key: ${AWS_SECRET_ACCESS_KEY:}
  s3:
    bucket: ${AWS_S3_BUCKET_NAME:}
    presign-ttl-seconds: 600
```

### 4) `AwsS3Properties` (`@ConfigurationProperties("aws")`)
- region, accessKey, secretKey, bucket, presignTtlSeconds 필드 바인딩
- `@Validated` 로 빈 값 차단

### 5) `S3Config` — 두 개의 빈
- `S3Client` (PutObject/DeleteObject/ListObjects 용)
- `S3Presigner` (presigned PUT/GET URL 용)
- 자격 증명: `StaticCredentialsProvider` + `AwsBasicCredentials`

### 6) 헬스 체크 (선택)
- 서버 기동 시 `HeadBucket` 1회 호출해 연결 확인 → 실패하면 로그 warn

## 완료 기준
- `./gradlew bootRun` 시 에러 없이 `S3Client` 빈이 주입됨
- `.env` 값이 `AwsS3Properties` 에 바인딩됨 (디버그 로그로 region/bucket 확인)

## 리스크
- 자격 증명이 로그에 찍히지 않도록 `toString()` 오버라이드 또는 `@ToString(exclude=...)`
- `.env` 가 gitignore 되어 있는지 재확인 (01 시작 전 검증)
