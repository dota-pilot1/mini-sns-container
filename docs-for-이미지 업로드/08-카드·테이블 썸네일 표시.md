# 08. 카드·테이블 목록에 대표 이미지 썸네일

## 목표
방 목록(카드뷰/테이블뷰) 에서 각 방의 대표 이미지를 작게 미리보기.

## 데이터 전략 — 3가지 중 택1

### (A) 목록 API 응답에 `primaryImageUrl` 포함 ← **권장**
- `GET /api/rooms` 의 각 항목에 필드 추가
- 서버에서 `findAllByRoomIdInAndIsPrimaryTrue` 로 일괄 조회 후 맵 조인
- N+1 없음, 추가 요청 없음

### (B) 별도 엔드포인트 `GET /api/rooms/primary-images?ids=1,2,3`
- 목록 응답을 건드리기 싫을 때
- 쿼리 1개 더 + React Query 합치기

### (C) 각 카드에서 개별 요청
- 가장 단순하지만 N+1, **절대 쓰지 말기**

## 서버 변경 (A 선택 시)

### `ListRoomsUseCase`
- 페이지 결과의 room id 들 수집
- `RoomImageRepository.findAllByRoomIdInAndIsPrimaryTrue(ids)` 로 한 번에 조회
- `Map<roomId, RoomImage>` 로 풀어서 응답 DTO 에 `primaryImageUrl` 주입

### 응답 DTO 수정
```java
public record RoomListItemResponse(
    Long id,
    String number,
    ...,
    String primaryImageUrl   // null 가능
) {}
```

## 프론트 변경

### `RoomCard`
- 카드 상단에 16:9 썸네일 영역
- `primaryImageUrl` 없으면 도형 placeholder (같은 비율, 아이콘)
- `loading="lazy"`, `onError` 로 placeholder fallback

### `RoomTableView`
- 첫 열에 32×32 정사각 썸네일
- 없으면 회색 박스 + 방번호 이니셜

## 성능
- S3 presigned GET URL 이면 TTL 이 짧아 매번 새로 발급됨 — 캐시 히트율↓
- **공개 URL 로 바꾸거나**, CloudFront 앞단에 두는 것이 이상적 (이 스텝 범위 밖)
- 일단 리스트 TTL 은 **응답 캐시 5분** 내외로 감내

## 완료 기준
- 새로 방 만들고 이미지 업로드 → 목록 새로고침 시 썸네일 바로 보임
- 대표 변경 → 목록 invalidation 후 썸네일 교체
- 이미지 없는 방도 레이아웃 깨지지 않음

## 마무리
- 이 스텝이 끝나면 00 의 DoD 가 모두 충족됨
- 후속 과제 (선택):
  - 드래그 재정렬 (07 에서 미뤘던 것)
  - CloudFront + 썸네일 리사이즈 (Lambda@Edge 또는 image CDN)
  - 고아 S3 객체 클린업 배치
