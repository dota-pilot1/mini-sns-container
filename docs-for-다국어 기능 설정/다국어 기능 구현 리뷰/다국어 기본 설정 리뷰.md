# 다국어 기본 설정 리뷰

## 문서 목적

이 문서는 현재 프론트 프로젝트의 다국어 기본 설정이 어떤 의미인지 정리한 문서입니다.

핵심은 아래 3가지입니다.
- 초기화 코드가 무슨 역할을 하는지
- 각 설정값이 무엇을 의미하는지
- namespace와 language가 어떻게 다르게 동작하는지

---

## 초기화 설정 상세 설명

현재 프로젝트의 기본 다국어 설정은 아래 코드 기준입니다.

```ts
void i18n.use(initReactI18next).init({
  resources,
  lng: 'ko',
  fallbackLng: 'en',
  defaultNS: 'common',
  ns: ['common', 'nav', 'home', 'auth', 'form'],
  interpolation: {
    escapeValue: false,
  },
})
```

파일:
- [src/shared/i18n/index.ts](/Users/terecal/mini-sns-conainer/mini-sns-front/src/shared/i18n/index.ts)

## 각 파라미터의 의미

### `i18n.use(initReactI18next)`

의미:
- i18next를 React와 연결하는 단계입니다.
- 이 설정이 있어야 React 컴포넌트 안에서 `useTranslation()`을 사용할 수 있습니다.

쉽게 말하면:
- i18n 엔진을 React 앱에 붙이는 과정입니다.

### `.init({...})`

의미:
- 다국어 시스템의 실제 초기 설정을 시작합니다.
- 어떤 언어를 기본으로 쓸지, 어떤 리소스를 등록할지, namespace를 어떻게 나눌지 여기서 정합니다.

### `resources`

```ts
resources
```

의미:
- 등록된 전체 언어 리소스 객체입니다.

현재 포함:
- `ko`
- `en`
- `ja`
- `zh`

쉽게 말하면:
- 실제 번역 문자열 사전 전체입니다.

### `lng: 'ko'`

```ts
lng: 'ko'
```

의미:
- 앱이 처음 시작할 때 기본 언어를 한국어로 두겠다는 뜻입니다.

중요:
- 이건 namespace 설정이 아닙니다.
- 현재 활성 언어의 기본값 설정입니다.

### `fallbackLng: 'en'`

```ts
fallbackLng: 'en'
```

의미:
- 현재 언어에서 번역 키를 찾지 못하면 영어 리소스를 대신 사용합니다.

예:
- 현재 언어가 `ja`
- 일본어에 특정 키가 없음
- 그럴 경우 영어 리소스를 참조

### `defaultNS: 'common'`

```ts
defaultNS: 'common'
```

의미:
- namespace를 생략하면 기본으로 `common`을 참조하겠다는 뜻입니다.

예:

```ts
t('signIn')
```

이렇게 쓰면 내부적으로 거의:

```ts
t('common:signIn')
```

처럼 동작합니다.

다만 현재 프로젝트에서는 혼동을 줄이기 위해 대부분 명시적으로 namespace를 붙여서 사용합니다.

### `ns: ['common', 'nav', 'home', 'auth', 'form']`

```ts
ns: ['common', 'nav', 'home', 'auth', 'form']
```

의미:
- 현재 프로젝트에서 사용할 namespace 목록입니다.

즉:
- `common`
- `nav`
- `home`
- `auth`
- `form`

이 다섯 그룹을 번역 문구의 기본 분류 기준으로 쓴다는 의미입니다.

### `interpolation`

```ts
interpolation: {
  escapeValue: false,
}
```

의미:
- 번역 문자열 안에 값을 끼워 넣을 때 동작하는 옵션입니다.

### `escapeValue: false`

```ts
escapeValue: false
```

의미:
- i18next에서 문자열 escape를 따로 하지 않겠다는 뜻입니다.

이유:
- React가 기본적으로 escape 처리를 해주기 때문입니다.
- i18next에서 또 escape하면 중복 처리될 수 있습니다.

## 관련 파일 구조

```text
mini-sns-front/src/shared/i18n
├── index.ts
└── resources
    ├── ko
    ├── en
    ├── ja
    └── zh
```

구조 의미:
- `index.ts`
  - i18n 초기화 전용 파일
- `resources/<언어>/`
  - 언어별 번역 리소스
- 각 언어 내부의 `common`, `nav`, `home`, `auth`, `form`
  - namespace 단위 파일

---

## namespace가 무엇인가

namespace는 번역 문구를 기능 또는 영역별로 나눈 그룹 이름입니다.

현재 프로젝트 기준:
- `common`
- `nav`
- `home`
- `auth`
- `form`

예:
- `common`: 공통 버튼, 공통 상태 문구
- `nav`: 헤더 메뉴
- `home`: 홈 화면 문구
- `auth`: 로그인/회원가입 관련 문구
- `form`: 폼 라벨, placeholder, 에러 메시지

쉽게 말하면:
- namespace는 번역 문구의 카테고리입니다.

---


## 실제 참조 방식

예를 들어:

```ts
t('auth:login.title')
```

이 코드는
- `auth` namespace에서
- `login.title` 키를 찾습니다.

이때 현재 언어가 `ko`면:

```ts
resources.ko.auth.login.title
```

현재 언어가 `en`면:

```ts
resources.en.auth.login.title
```

를 참조합니다.

즉:
- namespace는 그대로
- 현재 언어만 바뀌고
- 그 언어 안의 같은 namespace를 참조합니다

## 서버와 연동하면 무엇이 달라지나

서버와 연동해서 사용자별로 바뀌는 것은 `namespace`가 아니라 `언어(locale)`입니다.

즉 서버 연동으로 가능해지는 것은:
- 사용자별 언어 설정
- 사용자별 locale 저장
- 서버/프론트 메시지 기준 통일

예상 방식:
- 사용자 프로필에 locale 저장
- 로그인 후 사용자 locale을 응답으로 받기
- 또는 API 요청 시 `Accept-Language` 헤더 사용
- 프론트에서 `i18n.changeLanguage(userLocale)` 호출

정리:
- namespace는 프로젝트 구조상 거의 고정
- language(locale)는 사용자별로 달라질 수 있음

---

## 한 줄 요약

현재 다국어 기본 설정은 `어떤 언어 리소스를 등록할지`, `기본 언어를 무엇으로 할지`, `문구를 어떤 namespace로 나눌지`를 정하는 코드이며, 서버와 연동해서 사용자별로 달라질 수 있는 것은 `namespace`가 아니라 `language(locale)`입니다.
