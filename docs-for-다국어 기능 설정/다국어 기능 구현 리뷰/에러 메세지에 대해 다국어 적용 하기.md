# 에러 메세지에 대해 다국어 적용 하기

## 왜 필요한가

폼 에러 메시지는 개발자용 메시지가 아니라 `사용자에게 직접 보여주는 문구`입니다.  
그래서 사용자가 영어를 선택했으면 영어로, 일본어를 선택했으면 일본어로 보여야 합니다.

기존 문제:
- 로그인/회원가입 폼의 zod 에러 메시지가 한국어로 하드코딩되어 있었음
- 화면 라벨은 언어 변경이 되는데, 검증 메시지는 같이 바뀌지 않았음

즉:
- 화면 문구 다국어화는 되어 있었음
- 폼 검증 메시지 다국어화는 안 되어 있었음

---

## 수정한 방향

이번에는 아래 방식으로 적용했습니다.

1. 각 언어의 `form` namespace에 에러 메시지 추가
2. zod schema를 고정 상수가 아니라 `함수`로 변경
3. `t()`를 schema 생성 함수에 주입
4. 현재 언어 기준으로 에러 메시지가 생성되게 변경

---

## 어떤 점이 바뀌었나

### 1. 번역 리소스에 에러 메시지 추가

예:
- [ko/form.ts](/Users/terecal/mini-sns-conainer/mini-sns-front/src/shared/i18n/resources/ko/form.ts)
- [en/form.ts](/Users/terecal/mini-sns-conainer/mini-sns-front/src/shared/i18n/resources/en/form.ts)

추가한 키 예시:

```ts
errors: {
  invalidEmail: '...',
  nicknameMin: '...',
  passwordMin: '...',
  confirmPasswordRequired: '...',
  passwordMismatch: '...',
}
```

이제 폼 라벨뿐 아니라 검증 메시지도 언어 리소스에서 관리합니다.

### 2. 로그인 스키마를 함수로 변경

- [login-page.tsx](/mini-sns-front/src/routes/login-page.tsx)

이전:

```ts
const loginSchema = z.object({
  email: z.email('유효한 이메일을 입력하세요.'),
  password: z.string().min(8, '비밀번호는 8자 이상이어야 합니다.'),
})
```

현재:

```ts
const createLoginSchema = (t: TFunction) =>
  z.object({
    email: z.email(t('form:errors.invalidEmail')),
    password: z.string().min(8, t('form:errors.passwordMin')),
  })
```

즉, 하드코딩 문자열 대신 `t()`를 통해 현재 언어의 메시지를 가져오게 바뀌었습니다.

### 3. 회원가입 스키마도 같은 방식으로 변경

- [signup-page.tsx](/Users/terecal/mini-sns-conainer/mini-sns-front/src/routes/signup-page.tsx)

적용된 항목:
- 닉네임 최소 길이
- 이메일 형식
- 비밀번호 최소 길이
- 비밀번호 확인 입력
- 비밀번호 불일치

## 실제 사용 흐름

### 로그인

```ts
const { t } = useTranslation()
const loginSchema = createLoginSchema(t)

useForm({
  resolver: zodResolver(loginSchema),
})
```

### 회원가입

```ts
const { t } = useTranslation()
const signupSchema = createSignupSchema(t)

useForm({
  resolver: zodResolver(signupSchema),
})
```

이 흐름 때문에:
- 현재 언어가 한국어면 한국어 에러 메시지
- 현재 언어가 영어면 영어 에러 메시지

로 보여줄 수 있습니다.

---

## 장점

1. 사용자 언어 기준으로 검증 메시지가 보입니다.
2. 폼 라벨과 에러 메시지의 언어 기준이 맞춰집니다.
3. 새로운 에러 메시지가 필요하면 번역 리소스만 추가하면 됩니다.
4. 나중에 auth, post, comment 쪽 폼에도 같은 패턴을 재사용할 수 있습니다.

---

## 현재 남은 점

이번 작업으로 `에러 메시지 다국어화` 자체는 적용됐습니다.  
다만 아래는 아직 별도 작업이 필요합니다.

- 선택 언어 저장
- 브라우저 언어 자동 감지
- 서버 에러 메시지 locale 연동

즉, 프론트 폼 검증 메시지는 해결됐지만, 전체 locale 전략은 아직 확장 여지가 있습니다.

---

## 한 줄 정리

폼 검증 메시지를 하드코딩 문자열에서 번역 리소스 기반 구조로 바꿔서, 사용자가 선택한 언어에 맞는 에러 메시지가 보이도록 수정했습니다.
