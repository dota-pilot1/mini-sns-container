# 도메인 계층이 필요한 이유

아래의 코드를 보면서 살펴 보자

## 1. 도메인 객체를 생성하면서 동시에 내부에서 유효성 검사

```java
public static User register(UserId id, Email email, String passwordHash,
                            String name, Instant now) {
    if (passwordHash == null || passwordHash.isBlank())
        throw new IllegalArgumentException("passwordHash must not be blank");
    if (name == null || name.isBlank())
        throw new IllegalArgumentException("name must not be blank");
    return new User(id, email, passwordHash, name.trim(), now, now);
}
```

- `register()` 팩토리를 통과해야만 `User` 인스턴스가 생긴다
- 검증 실패 → 예외 → **유효하지 않은 객체는 애초에 존재할 수 없음**
- `Email` 타입이 들어온다는 것 자체가 이미 "이메일 규칙 통과함"을 보장 (`Email.of()`가 검증)

## 2. 객체 생성과 동시에 모든 데이터를 초기화

```java
Instant now = Instant.now(clock);
User user = User.register(
    UserId.generate(),
    email,
    passwordHash,
    command.name(),
    now
);
```

- **한 줄 = 완전히 유효한 User 완성**
- setter 없음 → 이후로도 계속 유효 상태 유지
- "반쪽 초기화된(half-initialized) 객체"가 메모리에 존재할 틈이 없음

## 핵심

> **"유효하지 않은 객체가 존재할 틈을 없앤다"**
> → 그 규칙을 모아두는 장소가 **도메인 계층**.
