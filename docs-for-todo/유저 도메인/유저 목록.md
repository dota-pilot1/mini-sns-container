# 유저 도메인 분리 + 리스트 조회 구현 계획 (DDD) — v1

## 0. 배경

- 고시원 운영 시스템 → 명백한 **멀티 도메인** (auth / user / room / contract / payment …)
- 현재 `User` 도메인이 `auth/` 에 섞여 있음 → **user 도메인으로 이동**
- 이동 후 `user/application/ListUsersUseCase` 추가
- 테이블은 **`users` 한 개 그대로** (auth/user는 같은 테이블을 공유하는 거의 유일한 예외 케이스)

## 1. v1 범위

| 항목 | v1 |
|---|---|
| `User` 도메인 `auth/` → `user/` 이동 | ✅ |
| `ListUsersUseCase` 추가 | ✅ |
| `GET /api/users` (페이징) | ✅ |
| 정렬 (`createdAt desc` 고정) | ✅ |
| 이메일 검색 | ❌ v2 |

| 인증/권한 | ❌ v2 |

## 2. 이동할 파일 (auth/ → user/)

```
auth/domain/model/User.java                    →  user/domain/model/User.java
auth/domain/model/Email.java                   →  user/domain/model/Email.java
auth/domain/model/UserId.java                  →  user/domain/model/UserId.java
auth/domain/exception/DuplicateEmailException  →  user/domain/exception/DuplicateEmailException
auth/domain/exception/InvalidEmailException    →  user/domain/exception/InvalidEmailException
auth/domain/repository/UserRepository.java     →  user/domain/repository/UserRepository.java
auth/infrastructure/persistence/UserJpaEntity         →  user/infrastructure/persistence/UserJpaEntity
auth/infrastructure/persistence/UserJpaRepository     →  user/infrastructure/persistence/UserJpaRepository
auth/infrastructure/persistence/UserRepositoryImpl    →  user/infrastructure/persistence/UserRepositoryImpl
```

**auth에 남는 것**
- `auth/domain/exception/WeakPasswordException` (비밀번호 정책은 auth 관심사)
- `auth/application/*` (SignupUseCase, Command/Result)
- `auth/presentation/*` (AuthController, AuthExceptionHandler, DTOs)

## 3. 신규 추가 파일

```
user/application/ListUsersUseCase.java
user/application/dto/ListUsersQuery.java
user/application/dto/ListUsersResult.java
user/presentation/UserController.java
user/presentation/dto/ListUsersResponse.java
```

## 4. 기존 파일 수정

- **`SignupUseCase`**: import 경로만 `auth.domain.*` → `user.domain.*` 변경
- **`AuthExceptionHandler`**: `basePackages` 제거(전역화) + InvalidEmailException / DuplicateEmailException import 경로 수정
- **`UserRepository`** (user로 이동한 파일): `findAll(Pageable)` 메서드 추가
- **`UserRepositoryImpl`**: `findAll(Pageable)` 구현 추가
- **`SecurityConfig`**: `/api/users/**` permitAll 추가

## 5. API 명세

### 요청
```http
GET /api/users?page=0&size=20
```

### 응답 (200)
```json
{
  "items": [

```

## 6. 작업 순서

1. user/ 패키지 하위 파일 새로 작성 (복사 + 패키지 선언 수정)
2. 기존 auth/ 하위 이동 대상 파일 삭제
3. SignupUseCase / AuthExceptionHandler import 경로 수정
4. UserRepository / UserRepositoryImpl 에 `findAll` 추가
5. user/application, user/presentation 신규 파일 작성
6. SecurityConfig 경로 추가
7. 빌드 + Swagger 검증

## 7. 테스트 체크리스트

- [ ] `GET /api/users` → 200
- [ ] 회원가입 직후 items 에 해당 유저 포함
- [ ] `?page=0&size=1` → totalPages 정확
- [ ] `?size=200` → 상한(100) 적용
- [ ] 응답에 `passwordHash` 포함 안 됨
- [ ] `createdAt` desc 정렬

## 8. 도메인 분리 원칙 (이후 도메인 추가 시 참고)

- **각 도메인 = 자기 테이블 소유** (room/rooms, contract/contracts, payment/payments ...)
- **예외**: auth/user는 같은 `users` 테이블을 공유 (인증 = 유저의 속성이라서)
- 다른 도메인끼리는 ID 참조만, 도메인 객체 직접 참조 금지

## 9. 한 줄 요약

> **"고시원은 멀티 도메인이니 User를 user/ 로 독립. auth는 user를 참조만. 테이블은 그대로 1개."**
