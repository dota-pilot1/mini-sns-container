# 다국어 관련 설정 리뷰

## 문서 목적

이 문서는 현재 프론트 프로젝트에서 다국어 설정이 어떻게 구성되어 있는지 빠르게 이해하기 위한 정리 문서입니다.

핵심은 아래 3가지입니다.
- 다국어 파일이 어디에 있는지
- 각 파일이 무슨 역할을 하는지
- 화면에서는 어떻게 사용하는지

지금처럼 정리하는 건 적절합니다.  
다만 `파일 구조`, `동작 흐름`, `확장 시 주의점`까지 같이 적어두는 편이 더 실무적으로 유용합니다.

---

# 다국어 관련 파일 구조

현재 다국어 설정은 아래 구조로 분리되어 있습니다.

```text
mini-sns-front/src/shared/i18n
├── index.ts
└── resources
    ├── ko
    │   ├── auth.ts
    │   ├── common.ts
    │   ├── form.ts
    │   ├── home.ts
    │   ├── index.ts
    │   └── nav.ts
    ├── en
    ├── ja
    └── zh
```

구조 의미:
- `index.ts`
  - i18n 초기화 전용 파일
- `resources/<언어>/`
  - 언어별 번역 리소스
- `common`, `nav`, `home`, `auth`, `form`
  - namespace 단위 분리

현재 지원 언어:
- `ko`
- `en`
- `ja`
- `zh`

# 프론트에서 어떻게 쓰나?

기본 사용 방식은 단순합니다.

## 1. 컴포넌트에서 `useTranslation` 사용

예시:

```tsx
import { useTranslation } from 'react-i18next'

export function Example() {
  const { t } = useTranslation()

  return <h1>{t('common:signIn')}</h1>
}
```

## 2. namespace:key 형태로 접근

현재 프로젝트는 namespace를 분리했기 때문에 아래처럼 사용합니다.

예시:
- `t('common:startNow')`
- `t('nav:login')`
- `t('home:title')`
- `t('auth:login.title')`
- `t('form:email')`

# 왜 지금 구조가 괜찮은가

현재 구조는 초기 단계 기준으로 적절합니다.

이유:
- 언어별 분리 완료
- namespace 분리 완료
- 공통 문구와 화면 문구가 섞이지 않음
- 기능이 늘어나면 namespace만 추가하면 됨

예를 들어 이후에 이런 식으로 확장할 수 있습니다.
- `post`
- `comment`
- `notification`
- `admin`
- `poll`

즉, 지금은 `초기 세팅치고는 꽤 올바르게 정리된 상태`입니다.

# 아직 남아 있는 보완 포인트

현재 구조가 충분히 좋아졌지만, 아래는 아직 남아 있습니다.

## 1. 선택 언어 저장

현재:
- 언어 변경은 가능
- 새로고침 후 유지 전략은 아직 없음

추천:
- localStorage 저장

## 2. 브라우저 언어 자동 감지

현재:
- 기본값 `ko`

추천:
- 저장된 언어가 없으면 브라우저 언어를 보고 초기 언어 결정

## 3. zod 검증 메시지 다국어화

현재:
- 폼 라벨은 번역됨
- zod 에러 문구는 한국어 하드코딩 상태

즉:
- 화면 문구 다국어화: 일부 완료
- 검증 메시지 다국어화: 아직 미완료

## 4. 필요 시 lazy loading

현재:
- 모든 언어 리소스를 한 번에 메모리에 올림

초기 규모에서는 문제 없음  
하지만 나중에 리소스가 커지면 동적 로딩 검토 가능

# 추천 QA 형식인지?

지금 사용한 제목:
- `다국어 관련 파일 구조`
- `주요 파일 및 기능 설명`
- `프론트에서 어떻게 쓰나?`

이 3개는 좋은 출발점입니다.  
다만 이것만 있으면 아래가 빠집니다.

- 이 구조가 왜 필요한지
- 지금 상태가 괜찮은지
- 앞으로 어디를 보완해야 하는지

그래서 아래 섹션을 추가하는 게 더 좋습니다.

- `문서 목적`
- `왜 지금 구조가 괜찮은가`
- `아직 남아 있는 보완 포인트`

즉, 현재 제목은 적절하지만 `조금 더 설명형 문서`로 보강하는 게 바람직합니다.
