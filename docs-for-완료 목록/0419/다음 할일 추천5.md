## 다음 6가지 (순서 확정)

### 1. 방 관리 강화 🏠

**할 일**
- 방 상세를 **드로어 → 별도 페이지** 로 분리 (`/rooms/:roomId`)
- 이미지 업로드 + 썸네일 갤러리 (여러 장, 대표 이미지 설정)
- 목록 카드/테이블에 대표 이미지 미리보기

**왜 1순위**
- 드로어 한계(좁음) 돌파 + 이미지가 방 식별력 크게 올림
- 이미지 스토리지(S3/로컬) 결정을 일찍 해야 이후 작업 영향 적음
- 후속 작업(입주 다이얼로그 이미지, 랜딩 페이지)의 재료가 됨

**범위**: 서버 이미지 업로드 API + 스토리지 + 프론트 상세 페이지. 3~5 커밋.

---

### 2. 입주 다이얼로그에 방 이미지 표시 🖼️

**할 일**
- `SelectedRoomDetail` 패널에 대표 이미지 2장 2열 그리드 + 라이트박스

**왜 2순위**: 1번 산출물 바로 활용, 관리자 배정 판단력 ↑. 1~2 커밋.

---

### 3. 결제 관리 (수동 입력) 💰

**할 일**
- `Payment` 애그리거트: `{ id, contractId, period, amount, paidAt, source, note, status }`
- **`source: MANUAL | TOSS | KAKAO | CASH`** 필드 미리 둠 → 나중 자동화 시 webhook 핸들러만 추가하면 됨
- 관리자가 월별 수동 입력 (계약별 "이번 달 입금 확인" 버튼 → Payment 레코드 생성)
- 입주자 드로어/방 상세에 "최근 입금 내역" 섹션
- 미납자 리스트 페이지

**왜 3순위**
- **실서비스 핵심 업무**. 매달 돌아오는 루틴 — 먼저 있어야 대시보드·포털이 의미 생김
- 수동 입력 먼저가 현실적. 토스페이 승인 후 `source=TOSS` webhook 붙이면 자동화 자연 확장

**범위**: 서버 1 커밋 + 프론트 2 커밋.

---

### 4. 대시보드 실구현 📊

**할 일**
- `/` 루트를 관리자 홈으로 재설계 (현재 랜딩은 6번에서 별도 처리)
- 위젯: 공실률 · 상태별 방 수 · 계약 만료 임박(7일 이내) · **이번 달 수금률(N/M)** · 오늘의 이슈(문제/청소)

**왜 4순위**
- 3번에서 결제 데이터가 생겨야 수금률 위젯이 의미 있음
- 월단위 계약 특성상 "만료 임박" 이 일상 업무의 핵심

**범위**: 2~3 커밋, 단일 페이지 재설계. 새 API 없이 기존 `/api/rooms`, `/api/contracts`, `/api/payments` 조합.

---

### 5. Role 3-tier + 입주자 포털 🔐

**할 일**
- `Role` enum: `OWNER`(건물주) / `MANAGER`(총무) / `TENANT`(입주자)
- JWT claims 에 role 포함, `@PreAuthorize` 로 엔드포인트 제한
- 프론트: 역할별 메뉴/라우트 가드
- **입주자 포털 (MVP 는 조회 전용)**: 내 계약 / 내 방 / 내 납부 내역 / 미납 알림

**왜 5순위**
- 계약·납부·대시보드 다 있으니 입주자 포털이 **빈 껍데기 아니라 실제 쓸모 있는 내용** 으로 채워짐
- 관리자 2-tier 만으로도 바로 실운영에 도움됨 (건물주가 총무에게 일부 권한 위임)

**범위**: 서버 2~3 커밋 + 프론트 3~4 커밋.

---

### 6. 랜딩 페이지 🏘️

**할 일**
- `/` 대신 외부 공개용 소개 페이지 (`/about` 또는 루트 분기)
- 건물 소개, 방 투어(1번의 이미지 재활용), 빈 방 리스트, 문의 폼
- 관리자/입주자는 로그인 후 자동 리다이렉트, 외부 방문자는 소개 페이지

**왜 마지막**
- 관리 도구 완성 후 외부 유입 고려가 자연스러움
- 이미지(1번) 결제(3번) Role(5번) 다 있어야 "빈 방 보고 문의 → 계약 → 입주" 끝까지 이어짐

**범위**: 1~2 커밋.

## 설계 원칙 메모

- **수동 먼저, 자동화 나중**: Payment `source` 필드로 확장 경로 열어둠
- **포털은 내용물이 채워진 뒤에**: 빈 껍데기 방지
- **이미지 스토리지 결정 빨리**: 1번에서 확정하면 이후 전부 재활용
